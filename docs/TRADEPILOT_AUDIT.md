Static code issues identified\n\nThese are findings from source inspection; they are not claimed as runtime failures until covered by tests/CI.\n\n### AUDIT-001 — Alembic model registration is incomplete — FIX IMPLEMENTED, CI PENDING\n**Priority:** P1\nbackend/alembic/env.py imports several newer models, including research and ML models, but does not visibly import the P10 validation models such as validation-day, validation-symbol and validation-manifest models.\n**Risk:** future Alembic autogenerate/metadata-based migration workflows may not see all current models.\n**Required action:** register every persistent model in Alembic metadata or establish and document an intentional alternative.\n\n### AUDIT-002 — Research instrument resolution should enforce NSE equity explicitly — FIX IMPLEMENTED, CI PENDING\n**Priority:** P1\nbackend/app/services/intraday_research_service.py resolves a symbol from the instrument master but does not visibly apply the same explicit exchange_segment == NSE_EQ filter used by the Dhan paper-validation service.\n**Risk:** ambiguous instrument-master rows could select a non-equity/non-NSE instrument.\n**Required action:** centralize and reuse the Indian NSE-equity resolver.\n\n### AUDIT-003 — Learning-event persistence is not transactionally coupled to PaperTrade persistence — FIX IMPLEMENTED, CI PENDING\n**Priority:** P1\npaper_dhan_service.py records the ML learning outcome before adding/committing the corresponding PaperTrade. record_trade_outcome() commits independently.\n**Risk:** a later PaperTrade persistence failure could leave a learning event without the corresponding persisted paper trade.\n**Required action:** make trade + learning-event persistence one transaction, or add a durable linkage/reconciliation invariant.\n\n### AUDIT-004 — Research data-quality checker has a weak timestamp/gap contract — FIX IMPLEMENTED, CI PENDING\n**Priority:** P1\nresearch_data_quality.py currently reports large_gaps as 0 and compares timestamp ordering through string conversion.\n**Risk:** the diagnostic can under-report interval gaps and can behave incorrectly for heterogeneous timestamp representations.\n**Required action:** normalize timestamps to timezone-aware datetimes and explicitly validate expected bar spacing/session boundaries.\n\n### AUDIT-005 — Research ingestion and validation logic are duplicated across paths\n**Priority:** P1\nDhan research ingestion, paper validation ingestion and historical-data validation each contain related symbol, diagnostics and provider-error handling.\n**Risk:** one path can become stricter/different from another and future fixes can be applied to one path only.\n**Required action:** create one shared historical-data contract/validator and reuse it across research, paper validation and backtesting ingestion.\n\n### AUDIT-006 — ML training thresholds are engineering gates, not evidence of profitability\n**Priority:** P1 / policy\nML validation uses fixed statistical thresholds such as accuracy/Brier/ROC-AUC. These are useful engineering checks but are not sufficient to establish trading edge.\n**Required action:** keep them explicitly labeled as model-quality gates and require separate trading-performance/OOS/cost evidence before any strategy promotion.\n\n### AUDIT-007 — Validation manifest is tamper-evident, not immutable\n**Priority:** P1 / policy\nThe manifest hash chain detects changes relative to the stored manifest, but an actor with database write access could rewrite both evidence and manifest.\n**Required action:** document this boundary and, for stronger auditability, add external append-only storage/signing when deployment infrastructure exists.\n\n### AUDIT-008 — Current repository head needs fresh CI verification\n**Priority:** P0\nThe repository has many commits after previously green CI runs. A historical green run must not be treated as proof that the latest head is green.\n**Required action:** require the latest head's backend, frontend, deployment-config and release-gate workflow to pass before marking the audit baseline green.\n\n## 5.
